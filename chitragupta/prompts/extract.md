Return JSON matching the schema, containing only durable, specific, reusable knowledge.

2. Be specific and cite evidence: class/method and file:line, schema.table.column, HTTP method + path, integration-engine channel/connector/transformer, HL7 segment-field (PID-3), FHIR path (Patient.identifier), config key, exact error text with data masked.
   Weak: "Fixed the notification bug."

7. Never output secrets or patient data. Describe structure, not values.
8. Compare with already_recorded: output only new items, or an update with "updates" set to the existing id when new information changes it.
9. Each "=== TURN ticket=X (src) ===" line names the ticket of the activity that follows it, until the next TURN line. Give each item that turn's ticket (or null to mean it), unless the item is explicitly about another candidate ticket. Set "time" to the HH:MM it happened.
